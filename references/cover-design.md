# Cover Design｜文章封面设计

## 1. 封面的任务

封面不是“给 AI 文章配一张科技图”。

它要把这篇文章最具体的对象和最值得点击的矛盾，翻译成一个一眼能懂的视觉场景。

判断标准：

> **去掉文章标题后，这张图本身还能不能让人猜到这篇大概在讲谁、讲什么关系？**

如果完全猜不到，说明封面太泛。

封面优先做到：

- 一眼看出本篇对象；
- 有明确内容锚点；
- 小缩略图里仍然成立；
- 有点击欲，但不靠夸张噱头；
- 美、克制、有编辑感；
- AI 味尽量低。

## 2. 先找“对象锚点”，再想画面

开始设计前，按这个顺序问：

1. 这篇文章真正的对象是谁？
2. 这个对象有没有天然视觉符号？
3. 文章最核心的关系是什么：对比、冲突、升级、发现、失败、变化，还是某种设计哲学？
4. 怎么把“对象 + 关系”变成画面？
5. 最后才考虑颜色、装饰和文字。

### 对象锚点可以来自

- 官方 Logo / mascot / 品牌视觉；
- 产品名本身的意象；
- 产品 UI / 官网 / 真实工作界面；
- 框架最具辨识度的结构；
- 某个真实使用场景；
- 本篇最关键的数据或物件。

例如：

- DeepSeek 可以自然使用其鲸鱼视觉语言，而不是随便放一个抽象“AI 大脑”；
- Pi Agent 可以从 Pi / π、极简、少工具、专注感里长出视觉；
- 如果文章讨论两个 Harness 的设计哲学，画面应该让“极简 vs 模块化”本身可视化，而不是只把两个产品名并排。

原则：

> **封面元素尽量从主题对象本身长出来，不从“AI 文章模板库”里挑。**

## 3. 唯美，但不能脱题

“唯美”不等于：

- 星球；
- 太阳；
- 宇宙；
- 山川；
- 柔光；
- 胶片；

这些元素只有在和主题对象、名字、故事或隐喻真正相关时才使用。

视觉可以很漂亮，但漂亮必须服务内容。

不要为了“高级感”添加与对象无关的宏大意象。

## 4. 统一审美，不统一模板

品牌统一不依赖：

- 固定绿色；
- 固定左标题右插图；
- 固定标签；
- 固定字体组合；
- 固定卡片；
- 固定赛博风。

长期统一来自一套审美判断：

- 干净；
- 具体；
- 克制；
- 信息密度适中；
- 有真实对象；
- 不廉价；
- 不像批量 AI 海报；
- 愿意为每篇内容重新找最合适的视觉语言。

> **统一的是判断，不是模板。**

不同文章完全可以长得不一样。

## 5. 常用构图方向

构图按主题选择，不固定。

### 对比 / PK

适合：模型、Agent、框架、产品路线差异。

可选：

- 左右分屏；
- 撕纸 / 拼贴；
- 同一场景里的两种世界；
- 同一个任务的两个工作台；
- 两种视觉语言正面对照。

重点不是“VS”本身，而是让两边的差异可见。

### 单产品 / 新发布

适合：新模型、新工具、新版本。

优先：

- 产品自身 Logo / mascot / UI；
- 一个强主视觉；
- 一个核心数字或一句极短标题；
- 能代表本次更新的真实功能场景。

### 机制 / 技术概念

适合：Harness、MCP、RAG、Sandbox 等。

优先把抽象机制翻译成一个具体可读的视觉隐喻，但不要把正文架构图直接做成封面。

## 6. 文字策略

封面不是正文摘要。

默认：

- 文字越少越好；
- 产品名 / 模型名可以大；
- 中文标题只保留最短、最有冲突的一句；
- 不把完整文章标题硬塞进去；
- 不做三四层副标题；
- 不靠一堆标签解释画面。

如果生图容易产生错字，优先生成少文字或无文字主视觉，再做准确文字后处理。

文字的任务是补画面，不是救一个没有内容锚点的画面。

## 7. 降低 AI 味

默认避免：

- 通用机器人；
- 发光大脑；
- 霓虹芯片；
- 漂浮方块；
- 渐变光球；
- 假 HUD；
- 假数据大屏；
- 没有真实意义的蓝紫赛博背景；
- 无缘无故的星球 / 宇宙 / 地球；
- 画面里堆满“AI”“AGENT”“LLM”等标签。

这些元素不是绝对不能用。

只有当它和本文主题直接相关，并且比真实对象锚点更合适时才使用。

## 8. 参考图怎么用

可以找优秀封面作为参考，但只蒸馏：

- 构图；
- 信息密度；
- 留白；
- 对比关系；
- 质感；
- 主体大小；
- 文字与画面的关系。

不要直接复制：

- 独特插画；
- 具体版式；
- 标志性视觉资产；
- 某位创作者固定人格化封面语言。

目标不是“做得像某个博主”，而是理解为什么那张图让人愿意点开。

## 9. 缩略图测试

公众号封面首先会以小图出现。

生成后必须缩小看一次：

- 主体还看得清吗？
- 两个对象还能分辨吗？
- 标题是否糊成一团？
- 画面是不是只有“好看”，但不知道在讲什么？
- 最重要的视觉信息是否集中在有效区域？

如果只能放大以后才成立，这张封面就还没完成。

## 10. 最终验收

每张封面生成后静默检查：

- [ ] 一眼知道这篇主要讲谁；
- [ ] 对象锚点来自主题本身，而不是泛 AI 元素；
- [ ] 核心关系已经视觉化；
- [ ] 画面漂亮、克制、有编辑感；
- [ ] 没有为了“唯美”加入无关意象；
- [ ] 没有固定模板感；
- [ ] 没有明显 AI 海报味；
- [ ] 文字足够少且准确；
- [ ] 小缩略图仍然看得懂；
- [ ] 如果把标题换成另一篇文章，这张图不能轻易复用。

最后一条很重要：

> **如果换个标题还能继续用，大概率说明封面太泛。**

## 11. 和发布 Runbook 的边界

本文件只负责：

- 封面审美；
- 内容锚点；
- 构图逻辑；
- 文字策略；
- 缩略图可读性；
- AI 味检查。

具体项目里的：

- 什么时候生成；
- 用哪个工具；
- 输出文件名；
- 保存目录；
- 裁剪 / 压缩；
- 本地预览；
- 仓库同步；
- 公众号发布；

属于项目 Runbook，不写进这里。

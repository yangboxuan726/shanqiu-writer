# Article Archetypes｜文章原型

不要给所有文章套“背景—定义—原理—优缺点—总结”。先判断这篇真正属于哪一种。

## 1. 热点 + 实测型

适合：模型发布、Agent 新产品、新工具上线。

优先顺序：
1. 发生了什么；
2. 最值得看的结果 / 数字 / 截图；
3. 山丘亲自测了什么；
4. 差异到底在哪；
5. 必要的官方定位、价格、benchmark；
6. 干净收尾。

不要先翻译完整发布会。

## 2. 实测体验型

适合：客户端、IDE、Agent、开发工具。

文章靠“现场”推进：
- 我为什么会装它；
- 第一次打开是什么感觉；
- 真跑任务后发生了什么；
- 哪一步舒服 / 难受；
- 截图、耗时、结果；
- 我最后怎么判断。

重点不是功能表，而是实际使用过程。

## 3. 一个问题讲明白型

适合：BM25、OAuth、MCP、RAG、缓存、事务等。

从一个真问题开始，例如：
- 都用大模型了，为什么还要 BM25？
- OAuth 为什么非要 code 换 token？

顺序：
1. 先给直觉答案；
2. 用一个具体例子把问题立住；
3. 机制自然被问题逼出来；
4. 必要时补术语 / 公式；
5. 回到工程里它到底有什么用。

## 4. 项目里第一次遇到型

适合：LiveKit、新中间件、新协议、新基础设施。

重点是：
- 我为什么遇到它；
- 我一开始怎么理解错了；
- 哪个比喻 / 心智模型让我突然懂了；
- 它在整个系统里到底站在哪。

## 5. 观点 / 观察型

适合：AI 使用方式、行业变化、个人方法论。

必须有具体材料做地基：
- 一次对话；
- 一个真实项目；
- 几个连续观察；
- 一次实验；
- 一个强烈反差。

不要从“随着 AI 快速发展”开始。

## 6. 教程 / 方法型

适合：真正需要读者跟着做的文章。

先给目标，再给最短路径。步骤要能执行，但不要把每一个按钮都解释成百科。

如果存在坑，优先写坑；如果没有必要，不要为了“完整教程”补背景知识。

# Visual Writing｜图文与排版

## 图是论据

优先级：
1. 作者亲测截图；
2. 官方发布页 / 官方博客截图；
3. 官方 / 可信作者 X 原帖；
4. 独立第三方图表；
5. 为解释复杂机制制作的原创图；
6. 纯氛围图最后考虑。

## 图片什么时候出现

热点 / 实测文章里，最有说服力的图尽量在前 20% 出现。

不要写了 1000 字，读者才第一次看到结果。

## 图下注释

来源必须让读者能判断，但**不要求每张图都机械写来源图注**。

如果图前的正文已经明确交代：

> “Pi 官方有一张图，写着 No MCP。”

然后紧接着就是那张图，那么读者已经知道它来自官方。此时不必再重复：

> 图：Pi 官网截图

更好的图注应该提供新增信息，例如：
- 这张图最值得看哪一句；
- 它证明了什么；
- 哪个细节容易被忽略；
- 这张图与前文哪个判断有关。

只有在以下情况里，优先补充来源说明：
- 读者无法从上下文判断是谁的图；
- 官方、第三方、作者亲测截图混在一起，容易混淆；
- 这张图承担一个关键事实判断；
- 图片或代码来自第三方，正文没有明确交代；
- 来源身份本身会影响读者如何理解这份证据。

原则：

> **来源要清楚，但不要为了规范感重复标注。**

图注不是固定元数据栏。没有新增信息时，可以没有图注。

## 复杂图表的读法

技术图表不能默认读者会读。

在图前或图后用一句人话告诉读者：
- 横纵轴最需要知道什么；
- 哪个区域更好；
- 本文只需要关注哪条线 / 哪两个点。

不要把图表说明写成论文图注，也不要逐项复述图上已经能看见的内容。

## 表格可以重复信息，但必须是“压缩”

正文已经讲过的信息，可以用表格在结尾或阶段节点压缩一次。

这是换一种介质收拢，不算无意义重复。

但不要正文讲一遍、表格抄一遍、表格后又用三段“综上”讲第三遍。

## 排版原则

视觉系统的第一层不是颜色，而是：

- 段落密度；
- 字号与字重；
- 行距与留白；
- 图文节奏；
- 强弱层级；
- 一屏里有没有新的东西。

默认基线改为**内容优先的中性排版**：

- 白底；
- 黑 / 深灰正文；
- 黑色粗体承担主要层级；
- 链接保留可点击视觉；
- 截图、代码、表格按内容本身需要出现；
- 不要求固定品牌色；
- 不为了“有设计感”强行加卡片、底色、色条。

品牌色可以存在，但只能是可选的小锚点，不是文章结构的必需品。

如果不用绿色，文章仍然应该完全成立。

判断标准：

> **把所有颜色去掉以后，层级、节奏和重点还清不清楚？**

如果不清楚，说明问题不在颜色，而在排版结构。

颜色不能代替阅读节奏。

## 小标题视觉

小标题不是默认必须品。

很多叙事型、体验型、现象分析型文章，可以从头到尾靠自然转场、短句、截图和留白推进，不一定需要明显的小标题。

真正需要小标题时，优先：

- 黑色或深灰；
- 字重 / 字号变化；
- 足够留白。

不要默认使用“绿色竖线 + 彩色标题”作为固定模板。

如果小标题一多，文章开始像 PPT、技术博客目录或知识库，就优先删标题，让正文自己过渡。

技术长文只有在读者确实需要定位时再使用小标题。

## 重点块

浅色卡片、引用块、表格只在确实能压缩信息时使用。

重点最常用的方式应该是：

- 一句话单独成段；
- 加粗；
- 前后留白；
- 紧接一张截图 / 代码 / 数据。

彩色底块是低频手段，不是默认强调方式。

连续出现多个重点块时，优先问：

> 如果全都强调，最后是不是等于都没强调？

不要为了“看起来设计过”把每三段包成一个卡片。

## CTA / 作者卡

正文结尾先完整结束。

关注卡、点赞、在看、转发属于排版层可选组件，不得破坏正文最后一句。

不是每篇都要 CTA。


## 封面不是正文配图

正文配图的第一职责是证明和解释。

封面的第一职责是让读者在很小的缩略图里认出本篇对象，并产生点击欲。

所以不要直接把正文里的架构图、流程图、Benchmark 图搬成封面。

封面审美与对象锚点规则详见 `cover-design.md`。

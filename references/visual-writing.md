# Visual Writing｜图文与排版

## 图是论据

优先级：
1. 作者亲测截图；
2. 官方发布页 / 官方博客截图；
3. 官方 / 可信作者 X 原帖；
4. 独立第三方图表；
5. 为解释复杂机制制作的原创图；
6. 纯氛围图最后考虑。

## 图片什么时候出现

热点 / 实测文章里，最有说服力的图尽量在前 20% 出现。

不要写了 1000 字，读者才第一次看到结果。

## 图下注释

图注尽量回答至少一个问题：
- 这图来自哪；
- 它证明什么；
- 读者应该看哪里。

不要写“图：某某截图”然后什么都没说。

## 复杂图表的读法

技术图表不能默认读者会读。

在图前或图后用一句人话告诉读者：
- 横纵轴最需要知道什么；
- 哪个区域更好；
- 本文只需要关注哪条线 / 哪两个点。

不要把图表说明写成论文图注，也不要逐项复述图上已经能看见的内容。

## 表格可以重复信息，但必须是“压缩”

正文已经讲过的信息，可以用表格在结尾或阶段节点压缩一次。

这是换一种介质收拢，不算无意义重复。

但不要正文讲一遍、表格抄一遍、表格后又用三段“综上”讲第三遍。

## 排版原则

视觉系统的第一层不是颜色，而是：
- 段落密度；
- 字号与行距；
- 留白；
- 图文节奏；
- 强弱层级。

品牌色只做少量强调，不要把整篇文章染成主题色。

“山丘风格”不等于“每个小标题都绿色”。

优先：
- 白底；
- 黑 / 深灰正文；
- 足够留白；
- 大图；
- 长短段落变化；
- 少量品牌色做锚点。

## 小标题视觉

不要每次逻辑切换都靠一个高存在感的彩色标题。

有些地方直接用一句自然过渡即可。

真正需要小标题时，它应该帮助读者定位，而不是把文章切成 PPT 模块。

## 重点块

浅色卡片、引用块、表格只在确实能压缩信息时使用。

不要为了“看起来设计过”把每三段包成一个卡片。

## CTA / 作者卡

正文结尾先完整结束。

关注卡、点赞、在看、转发属于排版层可选组件，不得破坏正文最后一句。

不是每篇都要 CTA。

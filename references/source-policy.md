# Source Policy｜事实与来源边界

## 四类来源必须分清

1. 官方说法；
2. 独立第三方测评；
3. X / 社区公开案例；
4. 山丘亲测。

不要把它们混成同一场 benchmark。

## 官方材料

适合证明：
- 发布时间；
- 官方定位；
- API 价格；
- 官方 benchmark；
- 产品功能声明。

官方 benchmark 不能自动等同于作者实际体验。

## 第三方案例

适合提供：
- 别人的实际展示；
- 更多任务类型；
- 额外视角。

写清是谁做的、条件是什么。没有统一条件时，不下“谁赢了”的结论。

## 作者亲测

只有实际做过的事才能写“我测了”。

保留真实过程，包括失败、卡住、重试、没搞懂。

## 静态图边界

静态截图可以评价：
- 构图；
- 场景元素；
- 视觉细节。

不能仅凭静态图判断：
- 动画是否自然；
- 快捷键是否生效；
- Agent 是否完整验证；
- 交互是否无 bug。

## 不确定时

直接写：
- “这点我现在不能确定。”
- “公开信息只能证明到这里。”

不要为了文章完整度补猜测。
